대상은 Windows 10, 11 (x64)이다.

## 한눈에 보기

| 공통 행동 | Windows에서 |
|---|---|
| 앱이 보이는 곳 | 위젯과 작업 표시줄 버튼. 트레이 없음 (WIN-10) |
| 가려진 위젯 꺼내기 (START-01) | 작업 표시줄 버튼 (WIN-11), 시작 메뉴나 바로가기로 다시 실행 (WIN-07) |
| 종료 (START-08) | ⋯ → 종료, 작업 표시줄 버튼 우클릭 → 창 닫기 (WIN-10) |
| 자동 실행 (START-02~05) | 레지스트리 Run 키 (WIN-03, WIN-04) |
| 데이터 폴더 | `%APPDATA%\TodoWidget\` (WIN-01) |
| 글꼴 (I18N-06) | 맑은 고딕, Segoe UI, Microsoft YaHei (WIN-08) |
| 설치 | 사용자 폴더, 관리자 권한 없음 (WIN-05, WIN-06) |

겉모양은 공통이다(WND-01). 그림자, 메뉴 모서리, 스크롤바처럼 OS 관례가 강한 부분만 Windows를 따른다.

## 요구사항

### WIN-01 데이터 폴더는 `%APPDATA%\TodoWidget\`이다
- 결과: `tasks.json`, `settings.json`과 백업 파일을 `%APPDATA%\TodoWidget\`(보통 `C:\Users\<사용자>\AppData\Roaming\TodoWidget\`)에 둔다. v1.4와 같은 폴더라서 v2.0을 설치하고 켜면 기존 할 일이 그대로 보인다(v1.4 형식이면 STORE-12로 변환한다). `TODOWIDGET_DATA_DIR`이 있으면 STORE-18을 따른다
- 확인: 자동 테스트

### WIN-02 작업 표시줄과 트레이에 나오지 않는다 (폐기)
- 결과: 2026-11-24 PM 결정으로 폐기했다. 작업 표시줄에는 WIN-10대로 버튼이 있다. 트레이에 아이콘이 없는 것은 WIN-10에 옮겼다
- 확인: 자동 테스트

### WIN-03 자동 실행은 레지스트리 Run 키에 등록한다
- 결과: START-02~05의 자동 실행 등록은 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`에 값 이름 `TodoWidget`으로 쓴다. 값은 지금 실행 파일 경로를 큰따옴표로 감싼 문자열이다(예: `"<실행 파일 경로>"`). v1.4와 같은 형식이다. 이 값이 있고, `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run`에 `TodoWidget`을 끈 것으로 표시하지 않았을 때만 켜진 것이다. 사용자가 작업 관리자의 시작 앱이나 설정 → 앱 → 시작프로그램에서 끄면 Run 값은 남고 이 표시만 생기므로, 그때는 꺼진 것으로 본다. ⋯ 메뉴로 켜면 Run 값을 쓰고 끈 표시를 지운다. 끄면 Run 값을 지운다. 켤 때 START-03의 경로 갱신은 Run 값 `TodoWidget`이 있으면 늘 한다. 끈 표시가 있어 꺼진 것으로 보는 때에도 Run 값의 경로만 지금 실행 파일로 바꾸고 끈 표시는 건드리지 않는다. 그래서 꺼진 상태는 그대로이고, 나중에 작업 관리자에서 다시 켜면 v1.4가 아니라 v2.0이 뜬다. Run 값이 없으면 아무것도 쓰지 않는다. ⋯ 메뉴의 체크 표시(켜짐 판정)는 위의 규칙 그대로다. 현재 사용자 키라서 관리자 권한이 필요 없다
- 확인: 자동 테스트

값 이름은 v1.4와 같아야 한다(WIN-04). 자동 실행 라이브러리가 다른 이름을 쓰면 직접 구현한다. v1.4는 끈 표시를 보지 않아서, 작업 관리자에서 끈 자동 실행도 ⋯ 메뉴에 켜짐으로 보였다. v2.0은 이 결함을 고친다.

### WIN-04 v1.4가 등록한 자동 실행을 이어받는다
- 조건: v1.4를 쓰던 PC다. `settings.json`이 있고, Run 키에 v1.4가 등록한 `TodoWidget` 값(v1.4 실행 파일 경로)이 있다
- 동작: v2.0을 설치하고 켠다
- 결과: 값 이름이 같으므로 START-03에 따라 `TodoWidget` 값을 v2.0 실행 파일 경로로 바꿔 쓴다. 새 값을 따로 만들지 않으므로 다음 로그인부터는 v2.0만 뜬다. v1.4에서 자동 실행을 꺼 두었으면 꺼진 채로 둔다. 값이 없으면 새로 만들지 않는다. 값은 있지만 WIN-03의 끈 표시가 있으면 WIN-03대로 값의 경로만 v2.0 실행 파일로 바꾸고 끈 표시는 그대로 둔다
- 확인: 자동 테스트

### WIN-05 설치 파일은 관리자 권한 없이 사용자 폴더에 설치한다
- 동작: NSIS 설치 파일(x64)을 실행한다
- 결과: 관리자 권한 확인(UAC) 없이 사용자 폴더에 설치된다. 시작 메뉴에 바로가기가 생기고, 설정 → 앱 → 설치된 앱(Windows 10은 설정 → 앱 → 앱 및 기능)에서 제거할 수 있다. 제거하면 Run 키의 `TodoWidget` 값도 지운다. 데이터 폴더(WIN-01)는 남는다. 서명하지 않은 설치 파일이라 첫 실행 때 SmartScreen 경고가 뜨면 "추가 정보" → "실행"으로 넘긴다
- 확인: 직접 확인

### WIN-06 WebView2가 없으면 설치 파일이 함께 설치한다
- 조건: WebView2 런타임이 없는 Windows 10
- 동작: 설치 파일을 실행한다
- 결과: 설치 파일이 WebView2 런타임을 함께 설치하고, 설치가 끝나면 위젯이 실행된다. 이미 WebView2가 있는 PC(Windows 11 기본)에서는 따로 설치하지 않는다
- 확인: 직접 확인

### WIN-07 다시 실행하면 가려진 위젯이 앞으로 온다
- 조건: 위젯이 다른 창에 가려져 있거나 최소화되어 있다(WIN-14)
- 동작: 시작 메뉴나 바로가기로 위젯을 다시 실행한다
- 결과: START-01대로 기존 위젯이 다른 창들 앞으로 오고, 새로 실행한 프로세스는 바로 끝난다. 작업 표시줄 버튼(WIN-11)을 누르는 것과 함께, Windows에서 가려진 위젯을 꺼내는 방법이다
- 확인: 직접 확인

### WIN-08 글꼴은 맑은 고딕, Segoe UI, Microsoft YaHei다
- 결과: I18N-06 글꼴 표의 Windows 열대로, 화면 언어가 한국어면 맑은 고딕, 영어·독일어면 Segoe UI, 중국어 간체면 Microsoft YaHei로 보인다. 모두 Windows 10·11에 기본으로 들어 있는 글꼴이라 따로 설치하지 않는다
- 확인: 직접 확인

### WIN-09 v1.4 데이터가 있는 PC에 설치하면 할 일이 그대로 보인다
- 조건: v1.4를 쓰던 PC다. `%APPDATA%\TodoWidget\`에 v1.4가 만든 `tasks.json`(할 일·하는 중·끝낸 일이 섞여 있다)과 `settings.json`이 있고, v1.4 자동 실행이 켜져 있다. v1.4는 종료해 두었다
- 동작: v2.0을 설치하고 켠다
- 결과: v1.4에서 보던 할 일이 제목·상태·순서 그대로 보이고, 창은 v1.4의 위치·크기·고정·투명도로 뜬다. 데이터 폴더에 `tasks.v1-backup-yyyyMMdd-HHmmss.json`이 생기고 `tasks.json`은 v2 형식으로 바뀐다(STORE-12). Run 키의 `TodoWidget` 값은 v2.0 실행 파일 경로로 바뀌어(WIN-04), 다시 로그인하면 v2.0만 뜬다
- 확인: 직접 확인

### WIN-10 작업 표시줄에 버튼이 있다
- 동작: 위젯을 켠다
- 결과: 작업 표시줄에 앱 아이콘 버튼이 하나 생긴다. Alt+Tab 목록에도 나온다. 알림 영역(트레이)에는 아이콘이 없다. 버튼을 우클릭해 "창 닫기"를 누르면 START-08처럼 위치를 저장하고 끝난다. 버튼을 우클릭해 작업 표시줄에 고정하면 위젯이 꺼져 있을 때도 아이콘이 남고, 위젯을 켜면 그 아이콘이 실행 중 버튼이 된다(버튼이 둘로 나뉘지 않는다). 고정은 사용자가 한다. 앱이 스스로 고정하지 않는다
- 확인: 직접 확인

### WIN-11 작업 표시줄 버튼으로 꺼내고 뒤로 보낸다
- 동작: 작업 표시줄 버튼을 누른다. 이어서 한 번 더 누른다
- 결과: 처음 누르면 위젯이 다른 창들 앞으로 온다. 최소화되어 있었으면 원래 위치로 나온다. 위젯이 활성 창일 때 누르면 최소화되지 않고 다른 창들 뒤로 가며, 그 전에 쓰던 창이 활성 창이 된다. 📌가 켜져 있으면(WND-09) 뒤로 가지 않고 맨 위에 그대로 있으며, 활성 창만 그 전에 쓰던 창으로 바뀐다. 다른 창을 누르면 그 창에 가려질 수 있는 것은 WND-09와 같다
- 확인: 직접 확인

### WIN-12 활성 창에 온 최소화 요청은 뒤로 보내기로 바꾼다
- 조건: 위젯이 활성 창이고 📌가 꺼져 있다, 활성 창이고 📌가 켜져 있다, 활성 창이 아니다
- 동작: Windows가 최소화를 요청한다(`WM_SYSCOMMAND`의 `SC_MINIMIZE`. 활성 창의 작업 표시줄 버튼을 누르면 온다)
- 결과: 차례대로 최소화하지 않고 뒤로 보내고 그 전에 쓰던 창을 활성 창으로 만든다, 최소화하지 않고 그 전에 쓰던 창을 활성 창으로만 만든다, 그대로 최소화한다. 창을 끄는 요청이나 닫는 요청 같은 다른 요청은 그대로 처리한다
- 확인: 자동 테스트

### WIN-13 최소화된 동안에는 위치를 저장하지도 창을 바꾸지도 않는다
- 조건: 위젯이 (300, 200)에 있다가 최소화됐다(모두 최소화 `Win+M` 등). 최소화된 창의 위치는 Windows가 화면 밖으로 알려 준다
- 동작: 0.5초가 지난다, 최소화된 채 종료한다(WND-14), 최소화된 동안 내용 높이가 바뀌거나 메뉴가 닫힌다, 최소화를 푼다
- 결과: 저장된 위치는 (300, 200) 그대로다(WND-02). 종료할 때도 위치를 새로 저장하지 않아, 다시 켜면 (300, 200)에 뜬다. 최소화된 동안에는 창 높이를 바꾸지 않고, 최소화를 풀면 그때 내용 높이에 맞추고(WND-03) 메뉴로 늘린 창을 되돌린다(WND-10). 푼 뒤에 옮기면 다시 저장한다
- 확인: 자동 테스트

### WIN-14 모두 최소화하면 위젯도 최소화된다
- 동작: `Win+M`을 누른다. 이어서 작업 표시줄 버튼을 누르거나 시작 메뉴로 다시 실행한다
- 결과: 다른 창들과 함께 위젯도 최소화된다. 버튼을 누르거나 다시 실행하면(WIN-07) 원래 위치와 크기로 앞에 나온다
- 확인: 직접 확인

## 참고: v1.4에서 v2.0으로 바꾸는 순간

요구사항이 아니라 안내다. 릴리스 안내(REL-07)에 적는다.

- v1.4가 켜져 있는 채로 v2.0을 설치하고 켜면 두 위젯이 함께 뜰 수 있다. v1.4와 v2.0은 두 번 실행을 막는 방식이 서로 달라서 서로를 알아보지 못하기 때문이다. 그래서 "기존 위젯을 먼저 종료하세요"라고 안내한다.
- 둘이 함께 떠 있으면 서로의 저장을 덮어쓸 수 있다. 함께 떴으면 v1.4를 ⋯ → 종료로 끈다. 둘이 똑같이 생겨 어느 쪽이 v1.4인지 모르겠으면 둘 다 ⋯ → 종료로 끄고 시작 메뉴에서 TodoWidget(v2.0)만 다시 켠다. 깜빡하고 그냥 두어도 다시 로그인하면 자동 실행이 v2.0만 띄운다(WIN-04).
- v1.4로 되돌리는 방법은 `behavior/storage.md`의 "참고: v1.4로 되돌리기"에 있다.

## 저장 파일

데이터 폴더는 OS마다 다르다. Windows는 WIN-01, macOS는 MAC-01에 적는다. Windows는 v1.4와 같은 폴더를 써서, v2.0을 설치하고 켜면 기존 할 일이 그대로 보인다.

데이터 폴더에는 이런 파일이 생긴다.

| 파일 | 내용 |
|---|---|
| `tasks.json` | 할 일 목록 |
| `settings.json` | 창 위치·크기, 맨 위 고정, 투명도, 섹션 접힘, 업데이트 확인 시각 |
| `tasks.broken-yyyyMMdd-HHmmss.json` | 깨진 `tasks.json`을 옮겨 둔 백업 (STORE-08) |
| `tasks.v1-backup-yyyyMMdd-HHmmss.json` | v1.4 형식 `tasks.json`을 변환하기 전에 복사해 둔 백업 (STORE-12) |

자동 실행을 켰는지는 파일에 저장하지 않는다. OS 자동 실행 등록 여부 자체가 기준이다(`behavior/startup.md` 용어의 "처음 실행", START-02).

## `tasks.json` 형식

```json
{
  "version": 2,
  "tasks": [
    {
      "id": "3f2a9c1e-...",
      "title": "보고서 초안 쓰기",
      "status": "todo",
      "createdAt": "2026-10-03T09:12:40+09:00",
      "completedAt": null
    }
  ]
}
```

- 할 일 하나의 필드와 상태값(`todo`, `doing`, `done`)은 v1.4와 같다. 시각 형식만 바뀌었다(STORE-05).
- 파일 전체를 `version`이 있는 객체로 감싼다. 나중에 형식이 또 바뀌어도 어느 버전 파일인지 알고 변환할 수 있게 하기 위해서다.
- `completedAt`은 끝낸 일에만 있고, 나머지는 `null`이다.
- 최상위 객체나 할 일 항목에 모르는 필드가 있으면 읽을 때 무시하고, 저장할 때는 쓰지 않는다.

## `settings.json` 항목

| 항목 | 형식 | 기본값 |
|---|---|---|
| `left`, `top` | 숫자 또는 null | null (WND-07) |
| `width`, `maxHeight` | 숫자 또는 null | null (WND-06) |
| `opacity` | 숫자 또는 null | null = 1.0 (WND-11) |
| `pinned` | 불리언 | true |
| `doneExpanded` | 불리언 | false |
| `todoExpanded` | 불리언 | true |
| `lastUpdateCheck` | STORE-05 형식의 시각 또는 null | null (UPD-01) |

v1.4의 항목은 이름과 뜻을 그대로 두고, v2.0에서는 `lastUpdateCheck`만 새로 더했다. 표에 없는 항목은 읽을 때 무시하고 저장할 때는 그대로 남긴다(STORE-15). 설정을 언제 저장하는지는 창(WND)과 시작·종료(START) 문서에 적는다.

## 요구사항

### STORE-01 바뀔 때마다 바로 저장한다
- 동작: 할 일을 추가하거나, 상태를 바꾸거나, 이름을 바꾸거나, 삭제하거나, 초기화한다
- 결과: 바뀔 때마다 바로 전체 목록을 `tasks.json`에 저장한다. 저장 버튼은 없다. 변경 없음(할 일 규칙 문서의 정의)이면 저장하지 않는다. 여러 줄을 붙여 넣어 여러 개를 한꺼번에 추가해도 저장은 한 번만 한다
- 확인: 자동 테스트

### STORE-02 저장은 원본을 깨뜨리지 않는다
- 동작: `tasks.json`이나 `settings.json`을 저장한다
- 결과: 같은 폴더의 임시 파일에 먼저 쓰고, 내용을 디스크에 flush한 뒤 원본과 바꾼다. 쓰는 도중 실패하거나 전원이 꺼져도 원본은 이전 내용 그대로 남는다. 저장이 끝나면 임시 파일이 남지 않는다. 데이터 폴더가 없으면 만든다
- 확인: 자동 테스트

### STORE-03 저장 파일은 사람이 읽을 수 있다
- 결과: `tasks.json`과 `settings.json`은 들여쓰기한 JSON이고, UTF-8(BOM 없음)로 쓴다. 한글·한자 같은 글자를 `\uXXXX`로 바꾸지 않아 메모장 같은 편집기로 그대로 읽을 수 있다
- 확인: 자동 테스트

### STORE-04 `tasks.json`은 v2 형식으로 저장한다
- 결과: 최상위는 `{ "version": 2, "tasks": [...] }`다. 항목마다 필드는 `id`, `title`, `status`, `createdAt`, `completedAt` 다섯 개다. `status`는 `todo`, `doing`, `done` 중 하나다. `tasks` 배열은 목록에 추가된 순서다(LIST-03이 이 순서를 쓴다)
- 확인: 자동 테스트

### STORE-05 시각은 PC 시간대를 포함한 ISO 8601로 기록한다
- 조건: PC 시간대가 UTC+2이고 지금 PC 시각이 2026-10-03 15:00:00.734다
- 결과: `createdAt`, `completedAt`은 `2026-10-03T15:00:00+02:00`처럼 `yyyy-MM-ddTHH:mm:ss±HH:MM` 형식으로 쓴다. 초 아래는 버린다. 시간대는 기록하는 순간의 PC 시간대다(서머타임이면 그때의 시차). UTC이면 `+00:00`으로 쓴다. 나중에 PC 시간대가 바뀌어도 이미 기록한 시각은 바꾸지 않는다
- 확인: 자동 테스트

### STORE-06 날짜 판단은 지금 PC의 시간대를 기준으로 한다
- 조건: 지금 PC 시간대가 UTC+2다. 두 시각 `2026-10-04T01:00:00+09:00`과 `2026-10-03T09:00:00+02:00`
- 결과: 같은 날인지는 두 시각을 지금 PC 시간대로 바꿔 날짜를 비교한다. 위 예에서 앞의 시각은 UTC+2로 2026-10-03 18:00이므로 둘은 같은 날이다. v2.0에는 이 규칙을 쓰는 기능이 없다(나중의 "끝낸 일 자동 정리"를 위한 규칙). 그래서 시각 비교 함수의 테스트로 확인한다
- 확인: 자동 테스트

### STORE-07 `tasks.json`이 없으면 빈 목록으로 시작한다
- 조건: 데이터 폴더에 `tasks.json`이 없다
- 결과: 빈 목록으로 시작하고 안내 줄에 아무것도 보여 주지 않는다. 파일은 첫 변경 때 만든다
- 확인: 자동 테스트

### STORE-08 깨진 `tasks.json`은 백업하고 빈 목록으로 시작한다
- 조건: `tasks.json`이 깨졌다. 깨짐은 JSON 문법 오류, 빈 파일, 최상위가 배열(v1.4 형식)도 `version`이 있는 객체도 아님, `version`이 2도 2보다 큰 정수도 아님, `version`이 2인데 `tasks`가 배열이 아님, 비어 있는(`null`) 항목, `id`·`title`이 없거나 문자열이 아니거나 빈 문자열·공백뿐, `status`가 `todo`·`doing`·`done`이 아님, `createdAt`이 없거나 시각 형식 오류, `completedAt`이 `null`이 아닌데 시각 형식 오류 중 하나다. 시각 형식은 v2 파일이면 STORE-05 형식, v1.4 파일이면 `yyyy-MM-dd HH:mm:ss`다. 맨 앞의 BOM 하나는 STORE-19대로 무시한 뒤 판단한다
- 결과: 파일 내용은 그대로 두고 이름만 `tasks.broken-yyyyMMdd-HHmmss.json`으로 바꾼다(지금 PC 시각, 예: `tasks.broken-20261003-090000.json`). 같은 이름이 이미 있으면 `-2`, `-3`처럼 번호를 붙여 기존 백업을 덮어쓰지 않는다. 빈 목록으로 시작하고 안내 줄에 `notice.backup`("저장 파일에 문제가 있어 백업해 두었어요")을 보여 준다. 이 안내는 위젯을 다시 켤 때까지 남는다. 첫 변경 때 새 `tasks.json`을 v2 형식으로 만든다
- 확인: 자동 테스트

### STORE-09 끝낸 일이 아닌 항목의 끝낸 시각은 무시한다
- 조건: 상태가 `todo`나 `doing`인데 `completedAt`에 형식이 맞는 시각이 있다. 또는 상태가 `done`인데 `completedAt`이 `null`이거나 `completedAt` 항목이 아예 없다
- 결과: 깨진 파일로 보지 않는다. 끝낸 일이 아닌 항목의 끝낸 시각은 없는 것으로 읽고, 다음 저장 때 `null`로 쓴다. `completedAt` 항목이 아예 없으면 상태와 관계없이 `null`로 읽는다(v1.4와 같다). 끝낸 시각이 없는 끝낸 일은 그대로 받아들여 끝낸 일 섹션 맨 아래에 둔다(LIST-05)
- 확인: 자동 테스트

### STORE-10 읽을 수 없는 `tasks.json`은 덮어쓰지 않는다
- 조건: `tasks.json`이 있지만 다른 프로그램이 잠가 두었거나 권한이 없어 STORE-20대로 다시 읽어도 읽지 못한다. 깨진 파일의 이름을 바꾸지 못할 때(STORE-08)도 같다
- 결과: 제목이 `app.title`("할 일")인 OS 대화 상자로 `error.cannotOpen`("할 일 파일을 열 수 없어요"), 파일 경로, 오류 내용을 보여 주고, 확인을 누르면 위젯을 띄우지 않고 끝난다. 빈 목록으로 시작하지 않으므로 원본 `tasks.json`은 그대로 남는다. 이때는 자동 실행 등록과 처음 실행의 `settings.json` 만들기(START-02)도 하지 않는다
- 확인: 자동 테스트

### STORE-11 저장에 실패하면 알리고 다음 변경 때 다시 저장한다
- 조건: `tasks.json`을 쓰지 못한다(권한 없음, 디스크 가득 참, 다른 프로그램이 잠금 등)
- 동작: 할 일을 바꾼다
- 결과: 바꾼 내용은 화면에 그대로 남고, 안내 줄에 `notice.saveFailed`("저장하지 못했어요. 다음 변경 때 다시 시도해요")를 보여 준다. 파일은 STORE-02에 따라 이전 내용 그대로다. 다음 변경 때 그 변경까지 포함한 전체 목록을 다시 저장하고, 성공하면 안내를 지운다. 변경 없음일 때와 종료할 때(START-08)는 다시 시도하지 않는다
- 확인: 자동 테스트

### STORE-12 v1.4 형식은 한 번 변환한다
- 조건: 위젯을 켰을 때 `tasks.json`의 최상위가 배열이다(v1.4 형식). 지금 PC 시각은 2026-10-03 09:00:00이다
- 결과: 먼저 원본을 `tasks.v1-backup-20261003-090000.json`으로 복사한다(이름 규칙은 `tasks.v1-backup-yyyyMMdd-HHmmss.json`, 같은 이름이 있으면 STORE-08처럼 `-2`, `-3`을 붙인다). 그다음 v1.4의 시각을 한국 표준시(`+09:00`)로 해석해 v2 형식으로 바꾸고 `tasks.json`에 저장한다. 실제 시각, 상태, 순서는 그대로다. 안내 줄에는 아무것도 보여 주지 않는다. 이미 v2 형식이면 백업도 변환도 하지 않는다. v1.4 형식이지만 깨졌으면 변환하지 않고 STORE-08을 따른다. 백업은 했지만 변환한 내용을 저장하지 못하면 STORE-11을 따른다
- 확인: 자동 테스트

    "title": "보고서 초안 쓰기",

    "createdAt": "2026-09-30 09:12:40",
    "completedAt": null
  },
  {
    "id": "b",
    "title": "은행 방문",
    "status": "done",
    "createdAt": "2026-09-29 08:00:00",

### STORE-13 변환용 백업에 실패하면 변환하지 않는다
- 조건: v1.4 형식 `tasks.json`을 읽었지만 `tasks.v1-backup-...` 복사에 실패한다(권한 없음, 디스크 가득 참 등)
- 결과: 변환하지 않고 원본 `tasks.json`을 그대로 둔다. 읽은 할 일은 화면에 보여 주지만 저장하지 않고, 안내 줄에 `notice.saveFailed`를 보여 준다. 할 일을 바꾸면 바꾼 내용은 화면에 남기고, 그때마다 STORE-12를 다시 시도한다(백업한 뒤 지금 목록을 v2 형식으로 저장). 성공하면 안내를 지운다
- 확인: 자동 테스트

### STORE-14 더 새 버전이 만든 파일은 건드리지 않는다
- 조건: `tasks.json`의 `version`이 `3`처럼 2보다 큰 정수다
- 결과: 할 일 목록을 읽지 않는다. 파일을 덮어쓰지도, 백업하지도, 이름을 바꾸지도 않는다. 빈 목록을 보여 주고 안내 줄에 `notice.newerFile`("새 버전에서 만든 파일이에요. 업데이트해 주세요")을 보여 준다. 위젯을 다시 켤 때까지 이 상태에서는 할 일을 바꿔도 `tasks.json`에 저장하지 않는다(바꾼 내용은 화면에만 있고, 저장 실패 안내도 띄우지 않는다). `settings.json`은 이 규칙이 아니라 STORE-15를 따른다(읽을 수 있는 항목은 쓰고, 모르는 항목은 저장할 때 남긴다)
- 확인: 자동 테스트

### STORE-15 `settings.json`이 없거나 깨지면 기본값을 쓴다
- 조건: `settings.json`이 없거나, 읽지 못하거나, 깨졌거나, 일부 항목이 빠지거나 틀렸거나, 모르는 항목이 섞여 있다
- 결과: 어느 경우든 안내는 없다. 파일이 없거나, 읽지 못하거나, JSON 문법 오류·빈 파일·`null`·객체가 아닌 값이면 모든 항목을 위 표의 기본값으로 쓴다. 객체로 읽히면 항목마다 따로 판단해서, 빠진 항목과 값이 틀린 항목(JSON 형식이 다름, 불리언 자리에 `null`, STORE-05 형식이 아닌 `lastUpdateCheck` 등)만 기본값을 쓰고 나머지 항목은 그대로 쓴다. 예를 들어 `{"left": 10, "pinned": "yes"}`이면 `left`는 10, `pinned`는 true다. `todoExpanded`가 없는 예전 파일은 할 일 섹션이 펼쳐진다. 맨 앞의 BOM 하나는 STORE-19대로 무시한 뒤 판단한다. 모르는 항목(v1.2의 `doingExpanded`, 더 새 버전이 더한 항목 등)은 읽을 때 무시하지만, 객체로 읽힌 파일이면 다음 설정 저장 때 그 항목을 이름과 값 그대로 남긴다. 예전 버전 앱이 새 버전 앱의 설정을 지우지 않게 하기 위해서다(STORE-14가 새 버전의 `tasks.json`을 건드리지 않는 것과 같은 뜻). 객체로 읽히지 않는 깨진 파일은 백업하지 않고, 다음 설정 저장 때 표의 항목만 써서 덮어쓴다. 다만 파일이 있는데 STORE-20대로 다시 읽어도 읽지 못했으면, 그 실행에서는 `settings.json`을 한 번도 쓰지 않는다. 창 이동·크기·고정·투명도·접힘을 바꾸면 화면에는 바로 적용하지만 저장하지 않고, 다음에 켤 때는 원래 파일의 설정을 쓴다. 잠깐 잠긴 파일을 기본값으로 덮어써 원래 설정을 잃지 않기 위해서다(STORE-10이 읽지 못한 `tasks.json`을 덮어쓰지 않는 것과 같은 뜻)
- 확인: 자동 테스트

### STORE-16 설정의 숫자가 비정상이면 null로 저장한다
- 조건: 저장하려는 `left`, `top`, `width`, `maxHeight`, `opacity` 중에 NaN이나 무한대가 있다
- 결과: 그 항목은 `null`로 저장하고 나머지 항목은 그대로 저장한다. JSON은 NaN·무한대를 담지 못하기 때문이다. 다음에 읽으면 그 항목은 기본값을 쓴다(WND-06, WND-07, WND-11)
- 확인: 자동 테스트

### STORE-17 설정 저장 실패는 조용히 넘어간다
- 조건: `settings.json`을 쓰지 못한다. 처음 실행의 파일 만들기(START-06), 창 이동·크기·고정·투명도 저장, 닫을 때의 저장(WND-14) 모두 해당한다
- 결과: 안내 줄에 아무것도 보여 주지 않고 위젯은 그대로 동작한다. 바꾼 설정은 지금 화면에 그대로 적용된 채이고, 다음 설정 저장 때 전체를 다시 쓴다(읽지 못한 `settings.json`이면 STORE-15대로 그 실행에서는 쓰지 않는다). `notice.saveFailed`는 `tasks.json` 저장 실패에만 쓴다(START-09)
- 확인: 자동 테스트

### STORE-18 개발 중에는 데이터 폴더를 바꿀 수 있다
- 조건: 환경 변수 `TODOWIDGET_DATA_DIR`에 폴더 경로가 들어 있다
- 결과: OS 기본 데이터 폴더(WIN-01, MAC-01) 대신 그 폴더에서 `tasks.json`과 `settings.json`을 읽고 쓰며, 백업 파일도 그 폴더에 만든다. 값이 없거나 빈 문자열이면 기본 폴더를 쓴다. 개발과 테스트 중에 실제 데이터를 건드리지 않기 위해서다
- 확인: 자동 테스트

### STORE-19 읽을 때 맨 앞의 BOM 하나는 무시한다
- 조건: `tasks.json`이나 `settings.json`이 UTF-8 BOM(바이트 `EF BB BF`)으로 시작한다. 메모장 같은 편집기로 고쳐 저장한 경우다
- 결과: 맨 앞의 BOM 하나는 없는 것으로 보고 나머지 내용을 읽는다. 그것만으로 깨진 파일(STORE-08)이나 기본값을 쓸 파일(STORE-15)로 보지 않는다. BOM이 두 개 이상이면 두 번째부터는 내용으로 보아 JSON 문법 오류다. 저장할 때는 STORE-03대로 BOM 없이 쓴다
- 확인: 자동 테스트

## 참고: v1.4로 되돌리기

요구사항이 아니라 안내다. v2.0 릴리스 안내에 적는다.

- v1.4는 v2 형식을 읽지 못한다. v2.0을 쓴 뒤 v1.4를 다시 실행하면 v1.4는 v2 파일을 깨진 파일로 보고 `tasks.broken-....json`으로 이름을 바꾼 뒤 빈 목록으로 시작한다. 데이터가 지워지지는 않는다.
- 되돌리려면 `tasks.v1-backup-....json`을 `tasks.json`으로 이름을 바꾼다. v2.0에서 바꾼 내용은 반영되지 않는다.
- `settings.json`은 v1.4도 그대로 읽는다. v1.4는 모르는 `lastUpdateCheck`를 무시한다.

- 확인: 자동 테스트

## 화면 구성

위에서부터 아래로 이 순서다.

1. 헤더 — 제목 `app.title`("할 일"), 남은 개수(`header.remaining`/`header.allDone`), 고정 버튼(WND-09), ⋯ 버튼(WND-10)
2. 끝낸 일 섹션 — 제목 줄 "끝낸 일 N · 펼치기/접기"(`status.done`, `section.doneShow`/`section.doneHide`). 항목이 0개면 섹션 자체가 안 보인다
3. 할 일 섹션 — 제목 줄 "할 일 N"(`status.todo`, 하는 중 포함). 항목이 0개면 섹션 자체가 안 보인다
4. 안내 줄 — 한 번에 안내 하나를 보여 주는 줄. 글이 길면 두 줄까지 줄바꿈된다. 저장 실패, 새 버전처럼 알릴 일이 있을 때만 보인다(START-09)
5. 입력칸 — 늘 보이는 할 일 추가 칸

끝낸 일 섹션과 할 일 섹션은 각자 접고 펼 수 있고, 펼쳤을 때는 섹션 안에서 따로 스크롤한다(LIST-16).

## 요구사항

### LIST-01 섹션은 위에서부터 끝낸 일, 할 일 순서다
- 결과: 화면에는 끝낸 일 섹션이 위, 할 일 섹션이 아래에 나온다. 항목이 0개인 섹션은 통째로 숨긴다
- 확인: 자동 테스트

### LIST-02 할 일 섹션은 하는 중이 위, 할 일이 아래다
- 결과: 할 일 섹션 안에서 하는 중 항목이 모두 위, 할 일 항목이 모두 아래에 온다. 각 그룹 안에서는 만든 시각이 오래된 것이 위다
- 확인: 자동 테스트

### LIST-03 같은 초에 만든 할 일은 추가한 순서를 지킨다
- 조건: 만든 시각이 같은 할 일 여러 개
- 결과: 만든 시각이 같으면 목록에 추가된 순서대로 보인다
- 확인: 자동 테스트

### LIST-04 끝낸 일은 최근에 끝낸 것이 위다
- 조건: 서로 다른 시간대에서 기록된 끝낸 시각이 섞여 있다
- 결과: 끝낸 시각을 문자열이 아니라 실제 시각(시점)으로 비교해 최근에 끝낸 것이 위로 온다. 시간대가 달라도 순서가 맞다
- 확인: 자동 테스트

### LIST-05 끝낸 시각이 없는 끝낸 일은 맨 아래다
- 조건: v1.4에서 만든 파일을 그대로 불러온 것처럼 끝낸 시각이 없는 끝낸 일이 섞여 있다
- 결과: 끝낸 시각이 없는 항목은 끝낸 일 섹션의 맨 아래에 온다
- 확인: 자동 테스트

### LIST-06 헤더에 남은 개수를 보여 준다
- 결과: 남은 개수가 1 이상이면 `header.remaining`("N개 남음")을, 0이면 `header.allDone`("모두 끝냈어요")을 보여 준다
- 확인: 자동 테스트

### LIST-07 끝낸 일 섹션은 접어 둘 수 있다
- 결과: 제목 줄 "끝낸 일 N · 펼치기/접기"를 누르면 펼침/접힘이 바뀐다. 제목 줄 오른쪽 글자는 접혀 있으면 `section.doneShow`("펼치기"), 펼쳐 있으면 `section.doneHide`("접기")다. 기본값은 접힘이다
- 확인: 자동 테스트

### LIST-08 할 일 섹션은 접어 둘 수 있다
- 결과: 제목 줄 "할 일 N"(N은 하는 중을 포함한 전체 개수)을 누르면 펼침/접힘이 바뀐다. 접혀 있어도 개수는 보인다. 기본값은 펼침이다
- 확인: 자동 테스트

### LIST-09 접힘 상태는 다음 실행 때 복원된다
- 결과: 펼침/접힘을 바꿀 때마다 `settings.json`의 `doneExpanded`, `todoExpanded`에 저장하고, 다음에 켤 때 그 값을 그대로 적용한다
- 확인: 자동 테스트

### LIST-10 할 일이 하나도 없으면 안내를 보여 준다
- 조건: 목록에 할 일이 하나도 없다
- 결과: 목록 자리에 `list.empty`("할 일을 추가해 보세요")를 보여 준다
- 확인: 자동 테스트

### LIST-11 긴 제목은 줄바꿈해서 전부 보여 준다
- 결과: 제목이 한 줄보다 길면 말줄임(…) 없이 줄을 바꿔 전부 보여 준다
- 확인: 직접 확인

### LIST-12 상태마다 표시가 다르다
- 결과: 할 일은 회색 빈 원, 하는 중은 주황 점이 있는 원 + 주황 배경, 끝낸 일은 초록 원 + 흐린 제목 + 가운데 줄(취소선)로 보인다. 할 일 섹션 제목 줄의 점은 주황, 끝낸 일 섹션 제목 줄의 점은 초록이다
- 확인: 직접 확인

### LIST-13 높이가 넉넉하면 섹션마다 필요한 만큼 쓴다
- 조건: 최대 높이가 없거나, 두 섹션이 필요한 높이의 합이 가용 높이 이하다. 예: 가용 400, 필요 [100, 200], 최소 [70, 74]
- 결과: 각 섹션은 늘거나 줄지 않고 필요한 높이를 그대로 쓴다. 위 예는 그대로 [100, 200]이 된다
- 확인: 자동 테스트

### LIST-14 높이가 모자라면 짧은 섹션은 다 보이고 긴 섹션들이 나머지를 똑같이 나눈다
- 조건: 섹션별 필요 높이의 합이 가용 높이보다 크다. v1.4 `SectionLayout.Allocate(가용 높이, 필요 높이들, 최소 높이들)` 예 — 짧은 것 하나 + 긴 것 하나: 가용 400, 필요 [100, 900], 최소 [70, 74] / 긴 것 둘: 가용 400, 필요 [600, 900], 최소 [70, 74]
- 결과: v1.4 `SectionLayout.Allocate`와 같은 배분을 한다 — 짧은 것 하나 + 긴 것 하나 → [100, 300] / 긴 것 둘 → [200, 200]. 어느 경우든 배분한 높이의 합은 가용 높이와 같다. 높이는 소수일 수 있으므로 테스트는 기대값과 0.01 이내면 같은 것으로 본다
- 확인: 자동 테스트

### LIST-15 섹션은 최소 높이 아래로 줄지 않는다
- 조건: 섹션별 최소 높이(제목 줄 + 첫 항목)의 합이 가용 높이 이상이다
- 결과: 각 섹션은 최소 높이를 그대로 받는다. 접힌 섹션은 제목 줄 높이만 최소값으로 쓴다
- 확인: 자동 테스트

### LIST-16 섹션마다 따로 스크롤한다
- 결과: 줄어든 섹션은 다른 섹션과 별개로 자기 영역 안에서 스크롤하고, 스크롤바는 얇다(화살표 없는 6px 폭)
- 확인: 직접 확인

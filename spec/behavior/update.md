# 업데이트

**변경 이력**
- 2026-10-03: 처음 작성 (v2.0 기준)
- 2026-10-03: UPD-04·UPD-07에 `notice.newerFile` 옆의 업데이트를 눌렀을 때 안내 줄이 어떻게 보이는지 적었다(START-09)
- 2026-10-03: UPD-07에서 실패 뒤에도 `update.action`을 남겨 바로 다시 시도할 수 있게 했다
- 2026-10-03: 최종 리뷰 반영 — 확인에 성공했을 때만 `lastUpdateCheck`를 쓰고 실패하면 1시간 뒤 다시 확인하며 잠자기에서 깨어나면 24시간이 지났는지 본다(UPD-01, UPD-06). `update.failed` 문구를 줄이고, 안내 줄 정의를 맞추고, UPD-09를 v2.0.1부터 pre-release로 확인하게 했다
- 2026-10-03: PM 승인 (v2.0 spec 기준선)

업데이트는 원칙 [PRIV-01](../00-principles.md)을 따른다. 네트워크 통신은 업데이트 확인과 다운로드뿐이고, 요청에 사용자 데이터를 담지 않는다.

v1.4에는 업데이트 기능이 없으므로 v2.0은 직접 설치한다. v2.0 다음 버전부터 위젯 안에서 업데이트한다.

## 용어

**`latest.json`**: 출시할 때 GitHub Release에 설치 파일과 함께 올리는 공개 파일. 최신 버전 번호와 OS별 업데이트 파일 주소, 서명이 들어 있다.

**새 버전**: `latest.json`의 버전 번호가 지금 실행 중인 버전보다 높은 것. 예를 들어 지금 2.0.0이면 2.1.0은 새 버전이고, 2.0.0과 1.9.0은 아니다.

**안내 줄**: 한 번에 안내 하나를 보여 주는 줄. 글이 길면 두 줄까지 줄바꿈된다(시작과 종료 문서 startup.md의 정의와 같다). 여러 안내가 겹치면 START-09의 우선순위를 따르고, 업데이트 안내(`update.available`, `update.installing`, `update.failed`)는 그중 가장 낮다. `notice.newerFile`과 함께 보이는 예외는 START-09에 적는다.

## 요구사항

### UPD-01 켤 때와 떠 있는 동안 하루 한 번 새 버전을 확인한다
- 조건: 위젯을 2026-10-03T09:00:00+09:00에 켜고 계속 띄워 둔다
- 결과: 켤 때 `settings.json`의 `lastUpdateCheck`와 관계없이 한 번 확인한다. 그 뒤에는 `lastUpdateCheck`로부터 24시간이 지나면 다시 확인한다(이 예에서 켤 때 확인에 성공했으면 2026-10-04T09:00:00+09:00 이후). 확인에 **성공했을 때만** 확인한 시각을 STORE-05 형식으로 `lastUpdateCheck`에 저장한다. 확인에 실패하면 `lastUpdateCheck`를 바꾸지 않고, 위젯이 떠 있는 동안 실패할 때마다 1시간 뒤에 다시 확인한다(UPD-06). 컴퓨터가 잠자기에서 깨어나면 지금 시각을 `lastUpdateCheck`와 비교해, 24시간이 지났거나 `lastUpdateCheck`가 없으면 바로 확인한다. `lastUpdateCheck`는 위젯이 계속 떠 있는 동안 다음 확인 시각을 정하는 데만 쓴다(켤 때는 늘 확인한다). 저장에 실패하면 STORE-17을 따른다
- 확인: 자동 테스트

### UPD-02 확인은 공개 파일 하나를 읽기만 한다
- 결과: 확인할 때 보내는 요청은 GitHub Release의 `latest.json`을 읽는 요청 하나다. 주소는 모든 사용자에게 같고, 요청에 할 일·설정·사용 기록을 담지 않는다. 확인만으로는 아무것도 받거나 설치하지 않는다
- 확인: 자동 테스트

### UPD-03 새 버전이 있으면 안내 줄로 알린다
- 조건: 지금 버전 2.0.0, `latest.json`의 버전 2.1.0
- 결과: 안내 줄(한 번에 안내 하나를 보여 주는 줄. 글이 길면 두 줄까지 줄바꿈된다)에 `update.available`("새 버전이 있어요")과 누를 수 있는 `update.action`("업데이트")을 "새 버전이 있어요 · 업데이트"처럼 함께 보여 준다. START-09에서 우선순위가 가장 낮으므로, 다른 안내가 있으면 그 안내가 사라진 뒤에 보인다. 다만 `notice.newerFile`이 보이는 동안에는 그 안내 옆에 `update.action`도 함께 보여 바로 업데이트할 수 있게 한다. `latest.json`의 버전이 2.0.0이나 1.9.0이면 아무것도 보여 주지 않는다. 확인에 성공했는데 새 버전이 없으면 보이던 `update.available` 안내를 지운다
- 확인: 자동 테스트

### UPD-04 업데이트를 누르면 받아서 설치하고 다시 띄운다
- 조건: UPD-03의 안내나 UPD-07의 다시 시도 안내(`update.failed` · `update.action`)가 보인다
- 동작: `update.action`을 누른다
- 결과: 안내 줄이 `update.installing`("업데이트하는 중이에요")으로 바뀌고, 이 동안은 다시 누를 수 없다. `notice.newerFile` 옆의 `update.action`을 눌렀을 때도 같아서, 설치하는 동안은 `notice.newerFile` 대신 `update.installing`만 보인다(START-09). `latest.json`에 적힌 업데이트 파일을 받아 서명을 확인한 뒤(UPD-08) 설치한다. 다시 띄우기 전에 종료할 때처럼 설정을 저장한다(WND-14). 끝나면 새 버전이 같은 위치·크기·설정으로 뜨고, 할 일도 그대로다
- 확인: 자동 테스트

### UPD-05 누르지 않으면 지금 버전을 계속 쓴다
- 조건: UPD-03의 안내가 보인다
- 동작: `update.action`을 누르지 않고 계속 쓰거나, 위젯을 끄고 다시 켠다
- 결과: 안내 줄만 남고 지금 버전이 그대로 동작한다. 사용자가 누르기 전에는 받거나 설치하지 않는다. 다시 켜면 UPD-01에 따라 확인하고, 새 버전이 여전히 있으면 다시 안내한다
- 확인: 자동 테스트

### UPD-06 확인에 실패하면 조용히 넘어간다
- 조건: 인터넷이 없거나, 서버가 오류를 돌려주거나, 응답이 없거나, `latest.json`을 읽을 수 없는 형식이다
- 결과: 안내 줄에 아무것도 보여 주지 않고 위젯은 그대로 동작한다. 앞서 보이던 `update.available`·`update.failed` 안내가 있으면 그대로 둔다. `lastUpdateCheck`는 바꾸지 않는다. 위젯이 떠 있으면 1시간 뒤에 다시 확인하고, 그 전에 끄면 다음에 켤 때 확인한다(UPD-01). 확인에 성공했을 때의 처리는 UPD-01, UPD-03, UPD-07에 적는다
- 확인: 자동 테스트

### UPD-07 받기나 설치에 실패하면 알린다
- 조건: `update.action`을 누른 뒤 업데이트 파일을 받지 못하거나(인터넷 끊김, 서버 오류) 설치하지 못한다
- 결과: 안내 줄에 `update.failed`("업데이트하지 못했어요")와 그 옆에 다시 시도하는 `update.action`("업데이트")을 "업데이트하지 못했어요 · 업데이트"처럼 함께 보여 준다. `update.action`을 다시 누르면 UPD-04대로 바로 다시 받아서 설치한다. `notice.newerFile` 옆의 `update.action`을 눌렀던 경우에는 `notice.newerFile`을 다시 보여 주고 그 옆에 `update.failed`와 `update.action`을 보여 준다(START-09). 문구가 길면 안내 줄은 두 줄까지 줄바꿈된다. 지금 버전이 그대로 동작하고 할 일과 설정도 그대로다. 이 안내는 다시 눌러 성공하거나 다음에 확인에 성공할 때(UPD-01)까지 남는다. 확인에 성공했을 때 새 버전이 여전히 있으면 `update.available`로 바뀌고(`notice.newerFile`이 보이는 중이면 그 옆에 `update.action`만 남고), 없으면 `update.action`과 함께 사라진다
- 확인: 자동 테스트

### UPD-08 서명이 맞지 않는 업데이트는 설치하지 않는다
- 조건: 받은 업데이트 파일의 서명이 없거나, 앱에 들어 있는 업데이트 전용 공개 키와 맞지 않는다
- 결과: 설치하지 않고 받은 파일을 버린다. 그 뒤는 UPD-07과 같이 처리한다
- 확인: 자동 테스트

### UPD-09 실제 업데이트를 두 OS에서 확인한다
- 조건: v2.0.1부터 출시할 때마다 한다(v2.0.0은 이전 버전인 v1.4에 업데이트 기능이 없다). 공개하기 전에 출시 후보를 GitHub pre-release로 올리고, 그 파일을 가리키는 시험용 `latest.json`을 따로 올린다. 이전 버전 태그에서 업데이트 주소만 시험용 `latest.json`으로 바꿔 만든 시험 빌드를 설치하고 할 일과 설정(위치, 크기, 고정, 투명도)을 바꿔 둔다. pre-release는 GitHub의 최신 릴리스로 잡히지 않으므로 사용자 위젯은 알아채지 못한다
- 결과: 시험 빌드에 "새 버전이 있어요 · 업데이트" 안내가 뜨고, 업데이트를 누르면 pre-release의 파일을 받아 설치한 뒤 새 버전으로 다시 뜬다. 다시 뜬 위젯에서 할 일과 설정이 그대로 유지된다. 확인이 끝나면 REL-04대로 PM 승인 뒤 정식 릴리스로 공개한다
- 확인: 직접 확인

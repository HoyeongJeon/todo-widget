# 입력과 조작

**변경 이력**
- 2026-10-03: 처음 작성 (v2.0 기준)

## 용어

**IME 조합 중**: 한글 두벌식, 중국어 병음 같은 입력기가 글자를 아직 확정하지 않은 상태. 조합 중에는 입력칸에 보이는 글자와 실제로 확정된 글자가 다를 수 있다. 조합을 끝내는(확정하는) 동작에도 보통 Enter를 쓰므로, 할 일 추가나 이름 바꾸기 저장에 쓰는 Enter와 겹칠 수 있다.

## 요구사항

### INPUT-01 입력칸은 항상 맨 아래에 떠 있다
- 결과: 목록 아래에 할 일을 추가하는 입력칸이 항상 보인다. 입력칸이 비어 있으면 `input.placeholder`("할 일 추가")를 흐리게 보여 주고, 글자가 있으면 숨긴다
- 확인: 자동 테스트

### INPUT-02 Enter를 누르면 추가하고 입력칸을 비운다
- 조건: 입력칸에 글자가 있다
- 동작: Enter를 누른다
- 결과: 그 글자로 할 일을 추가하고 입력칸을 비운다. 포커스는 입력칸에 남아 이어서 입력할 수 있다
- 확인: 자동 테스트

### INPUT-03 빈 입력에서 Enter는 아무것도 하지 않는다
- 조건: 입력칸이 비어 있거나 공백만 있다
- 동작: Enter를 누른다
- 결과: 아무것도 추가되지 않고 입력칸 내용도 그대로다(변경 없음)
- 확인: 자동 테스트

### INPUT-04 Esc를 누르면 입력하던 글자를 지운다
- 조건: 입력칸에 글자가 있다
- 동작: Esc를 누른다
- 결과: 입력칸이 빈다. 아무것도 추가되지 않는다
- 확인: 자동 테스트

### INPUT-05 IME 조합 중 Enter는 조합을 끝낸 뒤 정확히 하나를 추가한다
- 조건: 입력칸에서 "보고서 쓰"까지는 확정됐고 마지막 글자(예: "기")를 IME로 조합 중이다
- 동작: Enter를 누른다
- 결과: 조합을 확정하는 그 Enter 자체로는 추가하지 않는다. 확정이 끝나 입력칸 내용에 마지막 글자까지 반영된 뒤에 추가한다. 둘 중 어느 처리 방식을 쓰든(OS·입력기 관례를 따름) 바깥에서 보는 결과는 같다: 할 일 "보고서 쓰기"가 정확히 1개 추가되고, 마지막 글자가 빠지거나 두 번 추가되지 않는다. 추가가 끝나면 입력칸은 빈다
- 확인: 자동 테스트

### INPUT-06 IME 조합 중 Enter를 실제 입력기로 확인한다
- 결과: 한글 두벌식, 중국어 병음 입력기 각각으로 "글자 입력 → Enter → 바로 다음 글자 입력"을 이어서 해 보면 끊기거나 글자가 빠지지 않는다
- 확인: 직접 확인

### INPUT-07 여러 줄을 붙여 넣으면 줄마다 하나씩 바로 추가한다
- 조건: 줄바꿈이 있는 여러 줄 글
- 동작: 입력칸에 붙여 넣는다
- 결과: 입력칸에는 넣지 않고 줄마다 하나씩 할 일로 바로 추가한다. 붙여 넣은 순서대로 목록에 보인다
- 확인: 자동 테스트

### INPUT-08 여러 줄 붙여넣기에서 빈 줄은 건너뛴다
- 조건: 붙여 넣은 글 중 빈 줄이나 공백만 있는 줄이 섞여 있다
- 동작: 입력칸에 붙여 넣는다
- 결과: 빈 줄·공백 줄은 할 일이 되지 않고 건너뛴다
- 확인: 자동 테스트

### INPUT-09 줄 앞의 목록 기호 `-`, `•` 하나를 뗀다
- 조건: 붙여 넣은 줄 앞에 공백과 목록 기호 `-` 또는 `•`가 있다
- 동작: 입력칸에 붙여 넣는다
- 결과: 줄 앞 공백을 지운 뒤 맨 앞 기호 하나만 뗀다. `1.`처럼 숫자로 된 기호는 제목의 일부로 남긴다. 기호를 뗀 뒤 아무 글자도 남지 않는 줄은 INPUT-08에 따라 건너뛴다
- 확인: 자동 테스트

### INPUT-10 한 줄 붙여넣기는 입력칸에 그대로 들어간다
- 조건: 붙여 넣는 글에 줄바꿈이 없다
- 동작: 입력칸에 붙여 넣는다
- 결과: 일반 붙여넣기와 같이 입력칸 안에 그대로 들어간다. 할 일이 바로 추가되지는 않는다
- 확인: 자동 테스트

### INPUT-11 동그라미를 누르면 상태가 한 단계 바뀐다
- 조건: 할 일 하나
- 동작: 그 항목의 동그라미(상태 표시)를 누른다
- 결과: TASK-05의 순서(할 일 → 하는 중 → 끝낸 일 → 할 일)로 상태가 한 단계 바뀐다. 동그라미는 포커스를 가져가지 않으므로, 이름 바꾸기 중인 입력칸이 있으면(같은 할 일이든 다른 할 일이든) 상태를 바꾸기 전에 그 이름을 먼저 저장한다 (INPUT-14와 같은 저장 규칙)
- 확인: 자동 테스트

### INPUT-12 우클릭 메뉴로 상태를 바로 고르거나 이름을 바꾸거나 지운다
- 동작: 항목을 우클릭한다(macOS는 Control+클릭도 같다)
- 결과: 메뉴가 뜬다. 항목은 위에서부터 할 일 / 하는 중 / 끝낸 일 / 이름 바꾸기 / 삭제 순이다. 할 일 / 하는 중 / 끝낸 일 중 지금 상태에 체크 표시가 있다. 상태 항목을 고르면 TASK-10에 따라 그 상태로 바로 지정된다
- 확인: 자동 테스트

### INPUT-13 이름 바꾸기는 메뉴나 제목 더블클릭으로 시작한다
- 동작: 우클릭 메뉴의 "이름 바꾸기"를 고르거나 제목을 더블클릭한다
- 결과: 제목이 입력칸으로 바뀌고 포커스를 받으며 글자 전체가 선택된다
- 확인: 자동 테스트

### INPUT-14 Enter나 다른 곳 클릭으로 이름을 저장한다
- 조건: 이름 바꾸기 칸이 열려 있다. 마지막 글자를 IME로 조합 중일 수 있다
- 동작: Enter를 누르거나 다른 곳을 클릭해 포커스를 옮긴다
- 결과: 조합 중이던 마지막 글자까지 포함해 이름이 저장된다(TASK-11의 정리 규칙을 따른다). Enter와 포커스 이탈이 같이 일어나도 저장은 한 번만 한다
- 확인: 자동 테스트

### INPUT-15 Esc를 누르면 이름 바꾸기를 취소한다
- 조건: 이름 바꾸기 칸이 열려 있다
- 동작: Esc를 누른다
- 결과: 입력한 내용은 버리고 원래 제목으로 돌아간다. 저장하지 않는다
- 확인: 자동 테스트

### INPUT-16 이름 바꾸기 칸에 여러 줄을 붙여 넣으면 한 줄로 합친다
- 조건: 이름 바꾸기 칸이 열려 있다
- 동작: 줄바꿈이 있는 글을 붙여 넣는다
- 결과: 줄바꿈은 공백 하나로 바뀌어 커서(선택 영역) 자리에 들어가고, 붙여넣은 뒤 커서는 그 바로 뒤에 놓인다. 한 줄로 합쳐진 채 입력칸에 남고 바로 추가되지는 않는다
- 확인: 자동 테스트

### INPUT-17 삭제는 확인 없이 바로 지운다
- 조건: 할 일 하나
- 동작: 우클릭 메뉴에서 "삭제"를 고른다
- 결과: 확인 없이 바로 그 항목이 목록에서 사라진다
- 확인: 자동 테스트

### INPUT-18 초기화는 위젯 안에서 한 번 확인받는다
- 조건: 할 일이 1개 이상 있다
- 동작: ⋯ 메뉴에서 `menu.reset`("초기화")을 누른다
- 결과: 위젯 위에 확인 판이 뜬다. 내용은 `reset.question`("할 일 N개를 모두 지울까요?", N은 지금 전체 할 일 개수)과 `reset.warning`("지운 뒤에는 되돌릴 수 없어요."), 버튼은 `reset.cancel`("취소")과 `reset.confirm`("모두 지우기")이다. `reset.confirm`을 누르면 TASK-14에 따라 상태와 관계없이 모두 지운다. `reset.cancel`을 누르거나 판 바깥(옅게 덮인 부분)을 클릭하면 아무것도 지우지 않고 판만 닫힌다. 판이 열려 있는 동안에도 설정은 그대로다
- 확인: 자동 테스트

### INPUT-19 할 일이 없으면 초기화를 고를 수 없다
- 조건: 할 일이 0개다
- 결과: ⋯ 메뉴의 `menu.reset` 항목이 비활성 상태로 보여 고를 수 없다
- 확인: 자동 테스트

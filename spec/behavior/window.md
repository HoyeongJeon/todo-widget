# 창

**변경 이력**
- 2026-10-03: 처음 작성 (v2.0 기준)

## 용어

**크기와 좌표**: 모두 논리 픽셀이다(화면 배율을 적용하기 전 값). 창의 크기와 좌표는 카드 둘레의 그림자 여백(가로·세로 각 10)을 포함한 창 기준이다. 예를 들어 폭 320인 창의 카드 폭은 300이다.

**작업 영역**: 주 모니터 화면에서 OS가 작업 표시줄이나 메뉴 막대 같은 것으로 쓰는 부분을 뺀 영역.

**최대 높이**: 사용자가 정한 창 높이의 상한. 할 일이 적으면 창은 내용만큼만 크고, 많으면 최대 높이에서 멈춘 뒤 섹션마다 따로 스크롤한다(LIST-16).

## 요구사항

### WND-01 창은 테두리 없는 둥근 카드다
- 결과: OS 기본 테두리와 제목 표시줄이 없다. 둥근 모서리 카드만 보이고, 카드 밖은 투명하며 카드 둘레에 옅은 그림자가 있다
- 확인: 직접 확인

### WND-02 헤더를 끌어 창을 옮긴다
- 동작: 헤더에서 버튼이 아닌 부분을 눌러 끈다
- 결과: 창이 마우스를 따라 움직인다. 놓으면 그 위치(`settings.json`의 `left`, `top`)를 저장한다
- 확인: 자동 테스트

### WND-03 가장자리와 모서리를 끌어 크기를 바꾼다
- 동작: 카드 바깥 그림자 여백 안의 가장자리나 모서리를 잡아 끈다
- 결과: 끄는 동안 카드가 마우스를 그대로 따라온다(폭은 WND-04 범위 안에서). 놓은 높이가 최대 높이가 되고, 내용이 그보다 짧으면 창은 내용만큼 줄어든다. 놓으면 폭과 최대 높이를 WND-04·WND-05 범위로 맞춰 `settings.json`의 `width`, `maxHeight`에 저장한다
- 확인: 직접 확인

### WND-04 폭은 280~620이다
- 조건: 작업 영역 높이 1040. 저장된 폭이 100, 2000, 450인 경우
- 결과: 범위 밖 값은 가까운 끝으로 맞춘다. 100 → 280, 2000 → 620이 되고, 범위 안의 450은 그대로 450이다(카드 폭으로는 260~600)
- 확인: 자동 테스트

### WND-05 최대 높이는 300 이상, 작업 영역 높이 이하다
- 조건: 작업 영역 높이 1040. 저장된 최대 높이가 50, 3000, 700인 경우. 그리고 작업 영역 높이가 150이고 저장된 최대 높이가 없는 경우
- 결과: 50 → 300, 3000 → 1040(작업 영역 높이)이 되고, 범위 안의 700은 그대로 700이다. 작업 영역이 300보다 작아도 300은 허용한다. 작업 영역 높이 150에서도 최대 높이는 300이다. 300은 끝낸 일을 펼쳐 두어도 끝낸 일 1개, 할 일 1개, 입력칸이 보이는 높이다
- 확인: 자동 테스트

### WND-06 저장된 크기가 없거나 비정상이면 기본 크기를 쓴다
- 조건: 작업 영역 높이 1040. 저장된 폭과 최대 높이가 없거나, 폭이 NaN이고 최대 높이가 무한대인 경우
- 결과: 폭 320, 최대 높이 520(작업 영역 높이의 50%)을 쓴다. 기본 최대 높이도 300보다 작아지지 않는다. 폭과 최대 높이는 따로 판단해서, 하나만 없으면 그것만 기본값을 쓴다
- 확인: 자동 테스트

### WND-07 저장된 위치가 없으면 기본 위치에 띄운다
- 조건: 화면 하나(0, 0, 1920×1080), 작업 영역(0, 0, 1920×1040), 창 폭 320. 저장된 위치가 없거나, `left` 300만 있고 `top`이 없다
- 결과: 주 모니터 작업 영역 오른쪽 위에 여백 24를 두고 띄운다. 위 조건에서는 (1576, 24)다(1920 - 320 - 24, 0 + 24). 좌표가 하나만 있어도 기본 위치를 쓴다
- 확인: 자동 테스트

### WND-08 헤더를 잡을 수 있으면 저장된 위치를 쓴다
- 조건: 화면 하나(0, 0, 1920×1080), 작업 영역(0, 0, 1920×1040), 창 폭 320. 저장된 위치 (300, 200), (1800, 100), (2500, 100), (-2000, 100), (300, -500), (300, 1070). 그리고 왼쪽에 모니터가 하나 더 있어 화면 전체가 (-1920, 0, 3840×1080)일 때 저장된 위치 (-1500, 100)
- 결과: 창 위쪽 헤더 40만큼이 어느 모니터 영역 안에든 들어와 잡을 수 있으면 저장된 위치를 그대로 쓴다. 가로로는 창의 40 이상이 모니터 안에 있어야 하고, 세로로는 창 위 끝이 모니터 위 끝보다 위로 나가지 않고 위 끝부터 40이 모니터 아래 끝 안에 있어야 한다. 아니면 WND-07의 기본 위치를 쓴다. 위 예에서 (300, 200), 일부만 보이지만 헤더를 잡을 수 있는 (1800, 100), 왼쪽 모니터 위의 (-1500, 100)은 그대로 쓴다. 오른쪽 모니터를 뺀 (2500, 100), 왼쪽 모니터를 뺀 (-2000, 100), 위로 벗어난 (300, -500), 아래로 벗어나 헤더를 잡을 수 없는 (300, 1070)은 기본 위치 (1576, 24)로 띄운다
- 확인: 자동 테스트

### WND-09 📌로 맨 위 고정을 켜고 끈다
- 동작: 헤더의 📌 버튼을 누른다
- 결과: 맨 위 고정이 켜지면 위젯이 다른 창보다 늘 위에 뜨고, 꺼지면 일반 창처럼 다른 창에 가려질 수 있다. 기본은 켜짐이다. 켜짐은 진한 색의 고정 아이콘, 꺼짐은 흐린 색의 고정 해제 아이콘으로 눈으로 구분된다. 툴팁은 켜져 있을 때 `pin.on`("맨 위 고정 끄기"), 꺼져 있을 때 `pin.off`("맨 위에 고정")이다. 바꿀 때마다 `settings.json`의 `pinned`에 저장하고, 다음에 켤 때 그 값을 적용한다
- 확인: 자동 테스트

### WND-10 ⋯ 메뉴에는 자동 실행, 투명도, 초기화, 종료가 있다
- 동작: 헤더의 ⋯ 버튼을 누른다
- 결과: 메뉴 항목은 위에서부터 `menu.autoStart`("컴퓨터 켤 때 자동 실행", 체크 표시가 있다), `menu.transparency`("투명도") 이름과 그 오른쪽의 % 값, 그 아래 슬라이더, 구분선, `menu.reset`("초기화"), `menu.quit`("종료") 순이다. 메뉴는 ⋯ 버튼 바로 아래(간격 4)에 메뉴 오른쪽 끝을 ⋯ 버튼 오른쪽 끝에 맞춰 뜬다. 아래 공간이 모자라면 ⋯ 버튼 위로 뜬다
- 확인: 자동 테스트

### WND-11 배경 투명도는 0~40%를 1% 단위로 고른다
- 조건: `settings.json`의 `opacity`는 카드 배경의 불투명도이고, 슬라이더와 % 값은 투명도(= 1 - 불투명도)를 보여 준다
- 결과: 슬라이더 왼쪽 끝이 0%(불투명), 오른쪽 끝이 40%다. 고른 값은 1% 단위로 반올림한다(14.6 → 15% → 불투명도 0.85). 저장값은 불투명도 1.0~0.6이다. 범위 밖 값은 가까운 끝으로 맞춘다(저장값 0.1 → 0.6, 1.5 → 1.0 / 투명도 70% → 40%, -5% → 0%). 저장값이 없거나 NaN이면 0%(불투명도 1.0)다. 불투명도 0.85는 15%, 0.6은 40%로 표시한다
- 확인: 자동 테스트

### WND-12 투명도는 끄는 동안 바로 보이고 메뉴를 닫을 때 한 번 저장한다
- 동작: ⋯ 메뉴의 투명도 슬라이더를 끌거나 누르거나, 슬라이더 위에서 마우스 휠을 굴린다
- 결과: 값이 바뀔 때마다 카드 배경과 % 값에 바로 반영한다. 휠은 한 칸에 2%씩 바꾼다(위로 굴리면 더 투명하게, 아래로 굴리면 덜 투명하게, 0~40% 안에서). 저장은 메뉴가 닫힐 때 값이 바뀌었으면 한 번만 한다. 바뀌지 않았으면 저장하지 않는다
- 확인: 자동 테스트

### WND-13 투명도는 배경에만 적용된다
- 조건: 투명도를 40%로 둔다
- 결과: 카드 배경, 끝낸 일 섹션 제목 줄 배경, 하는 중 항목의 배경이 비쳐 뒤가 보인다. 글자와 동그라미는 그대로 선명하다. 카드 그림자도 불투명도에 맞춰 함께 옅어진다
- 확인: 직접 확인

### WND-14 창을 닫을 때 위치와 접힘 상태를 저장한다
- 동작: 위젯을 종료한다(START-08)
- 결과: 닫히기 직전에 지금 창 위치(`left`, `top`)와 두 섹션의 펼침/접힘(`doneExpanded`, `todoExpanded`)을 다른 설정과 함께 `settings.json`에 저장한다. 설정 저장에 실패해도 알리지 않고 그대로 닫는다
- 확인: 자동 테스트

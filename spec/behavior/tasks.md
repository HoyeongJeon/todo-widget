# 할 일과 상태

**변경 이력**
- 2026-10-03: 처음 작성 (v2.0 기준)
- 2026-10-03: 최종 리뷰 반영 — TASK-03에 공백의 범위(Unicode White_Space)를, TASK-11에 같은 제목으로 바꾸면 변경 없음임을 적었다

## 용어

할 일 하나의 상태는 세 가지다. 저장할 때 쓰는 값과 화면에 보이는 이름(I18N 사전 키)은 다르다.

| 저장값 | 화면 이름 (I18N 키) |
|---|---|
| `todo` | 할 일 (`status.todo`) |
| `doing` | 하는 중 (`status.doing`) |
| `done` | 끝낸 일 (`status.done`) |

## 변경 없음

이 문서에서 "변경 없음"은 목록을 바꾸지 않는다는 뜻이다. 저장하지 않고 화면도 다시 그리지 않는다(저장 규칙은 STORE-01 참고).

## 요구사항

### TASK-01 새 할 일은 할 일 상태로 만들어진다
- 조건: 제목 "보고서 초안 쓰기"
- 동작: 할 일을 추가한다
- 결과: 상태는 `todo`이고, 만든 시각은 추가한 시각이며, 끝낸 시각은 없다
- 확인: 자동 테스트

### TASK-02 할 일마다 서로 다른 id를 가진다
- 동작: 할 일을 여러 번 추가한다
- 결과: 추가할 때마다 겹치지 않는 GUID 문자열 id를 받는다
- 확인: 자동 테스트

### TASK-03 제목의 공백을 정리한다
- 조건: 제목 `"  보고서\n  쓰기\t "`
- 동작: 할 일을 추가한다
- 결과: 줄바꿈·탭·연속 공백은 공백 하나로 합쳐지고 앞뒤 공백은 지워져 `"보고서 쓰기"`가 된다. 여기서 공백은 Unicode White_Space 문자 전부다. 전각 공백(U+3000)도 공백이고, U+FEFF(BOM, 폭 없는 줄바꿈 금지 공백)는 공백이 아니다. v1.4와 같다
- 확인: 자동 테스트

### TASK-04 정리하고 나서 빈 제목이면 추가하지 않는다
- 조건: 제목이 `""`, `"   "`, `"\n\t"` 중 하나
- 동작: 할 일을 추가한다
- 결과: 정리한 뒤 빈 문자열이면 아무것도 추가되지 않고 목록은 그대로다
- 확인: 자동 테스트

### TASK-05 상태는 할 일 → 하는 중 → 끝낸 일 → 할 일로 돈다
- 조건: 상태 `todo`인 할 일
- 동작: 상태 순환을 세 번 한다
- 결과: `todo` → `doing` → `done` → `todo` 순으로 바뀌어 세 번째에 처음 상태로 돌아온다
- 확인: 자동 테스트

### TASK-06 끝낸 일이 되면 끝낸 시각을 기록한다
- 조건: 상태 `doing`인 할 일, 지금 `2026-10-03T09:30:00+09:00`
- 동작: 상태를 `done`으로 바꾼다(순환이든 지정이든)
- 결과: 끝낸 시각은 `2026-10-03T09:30:00+09:00`이다
- 확인: 자동 테스트

### TASK-07 끝낸 일에서 벗어나면 끝낸 시각을 지운다
- 조건: 상태 `done`이고 끝낸 시각이 있는 할 일
- 동작: 상태를 `done`이 아닌 다른 상태로 바꾼다
- 결과: 끝낸 시각은 없다
- 확인: 자동 테스트

### TASK-08 다시 끝내면 새 시각을 기록한다
- 조건: 한 번 끝냈다가 다른 상태로 바뀐 할 일. 지금은 그때보다 1시간 뒤다
- 동작: 다시 상태를 `done`으로 바꾼다
- 결과: 끝낸 시각은 이전에 끝냈던 시각이 아니라 지금 시각이다
- 확인: 자동 테스트

### TASK-09 이미 끝낸 일을 다시 끝낸 일로 지정하면 아무것도 바뀌지 않는다
- 조건: 상태 `done`, 끝낸 시각 `2026-10-03T09:00:00+09:00`
- 동작: 상태를 `done`으로 지정한다
- 결과: 끝낸 시각은 그대로 `2026-10-03T09:00:00+09:00`이고, 저장도 화면 갱신도 일어나지 않는다
- 확인: 자동 테스트

### TASK-10 상태를 바로 지정할 수 있다
- 조건: 할 일 하나
- 동작: 상태를 `todo`·`doing`·`done` 중 하나로 지정한다
- 결과: 어느 상태로든 한 번에 바뀌고 TASK-06~09의 규칙을 따른다. 지금 상태와 같은 상태로 지정하면 변경 없음이다
- 확인: 자동 테스트

### TASK-11 이름을 바꿀 때도 같은 정리 규칙을 쓴다
- 조건: 제목 "초안"인 할 일
- 동작: 이름을 `"  보고서\n초안  "`으로 바꾼다
- 결과: TASK-03과 같은 정리를 거쳐 제목이 "보고서 초안"으로 바뀐다. 정리한 제목이 지금 제목과 같으면(예: `"  초안 "`으로 바꾸기) 변경 없음이다
- 확인: 자동 테스트

### TASK-12 빈 제목으로는 이름을 바꿀 수 없다
- 조건: 제목 "초안"인 할 일
- 동작: 이름을 "   "으로 바꾼다
- 결과: 정리한 뒤 빈 문자열이면 바뀌지 않는다. 제목은 "초안" 그대로이고 변경 없음이다
- 확인: 자동 테스트

### TASK-13 할 일을 삭제한다
- 조건: 할 일 두 개
- 동작: 그중 하나를 삭제한다
- 결과: 그 할 일만 목록에서 사라지고 나머지는 그대로 남는다
- 확인: 자동 테스트

### TASK-14 모두 지우면 상태와 관계없이 전부 사라진다
- 조건: 할 일, 하는 중, 끝낸 일이 섞인 목록
- 동작: 모두 지우기를 실행한다
- 결과: 상태와 관계없이 모든 할 일이 사라진다. 목록이 이미 비어 있으면 아무것도 바뀌지 않는다(변경 없음)
- 확인: 자동 테스트

### TASK-15 없는 id로 조작하면 아무것도 바뀌지 않는다
- 조건: 목록에 없는 id
- 동작: 그 id로 상태 순환, 상태 지정, 이름 바꾸기, 삭제 중 하나를 시도한다
- 결과: 네 조작 모두 변경 없음이고 목록은 그대로다
- 확인: 자동 테스트

### TASK-16 남은 개수는 할 일과 하는 중의 합이다
- 조건: 할 일, 하는 중, 끝낸 일이 섞인 목록
- 결과: 남은 개수는 상태가 `todo`이거나 `doing`인 항목 수의 합이다. 끝낸 일은 세지 않는다
- 확인: 자동 테스트

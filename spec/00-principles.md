## 제품 원칙

- 늘 떠 있는 작은 위젯으로, 남은 일을 한눈에 보여 준다. 성공 기준은 설계 문서 1장에 있다.
- 행동은 두 OS가 같게, 겉모양은 각 OS에 맞게 한다.
- 배경 투명도는 필수 기능이다. App Store 배포는 하지 않는다.
- 혼자 또는 지인 몇 명이 각자 PC에서 쓴다. 동기화·공유·계정은 없다.

## 개발 원칙

CLAUDE.md "작업 규칙"과 설계 문서 5장을 요약한다.

- spec이 먼저다. 동작을 바꾸려면 spec 수정 → PM 승인 → 실패하는 테스트 → 구현 → 리팩터링 순서로 간다. 코드와 spec이 다르면 코드가 틀린 것이다.
- TDD를 따른다. 테스트 없는 동작 코드는 넣지 않는다.
- clean architecture 층 구조(domain / application / presentation / adapters)와 의존 방향을 지킨다. 의존 방향은 lint 규칙으로 막는다.
- OS에 따라 다른 코드는 정해진 위치에만 둔다(설계 문서 5.4).
- 모든 의존은 constructor로 주입하는 port를 쓴다. 전역 singleton은 쓰지 않는다.

## 요구사항

### PRIV-01 사용자 데이터는 기기 밖으로 나가지 않는다
- 조건: 앱의 모든 소스 코드
- 결과: 네트워크 요청을 보내는 코드는 updater adapter 하나뿐이고, 그 요청에는 할 일·설정·사용 기록을 담지 않는다. updater adapter가 아닌 코드에서는 `fetch`, `XMLHttpRequest`, `WebSocket`, Tauri http plugin을 쓰지 않는다.
- 확인: 자동 테스트

### PERF-01 켜고 1초 안에 위젯이 보인다
- 결과: 실행부터 위젯이 화면에 그려질 때까지 1초 이내다.
- 확인: 직접 확인

### PERF-02 조작 결과가 바로 보인다
- 결과: 추가·상태 변경·접기 후 체감 지연 없이 화면에 반영된다.
- 확인: 직접 확인

### PERF-03 가만히 있을 때 CPU를 거의 쓰지 않는다
- 조건: 조작 없이 1분 동안 그대로 둔다
- 결과: 그 1분 동안 CPU 평균 사용률이 1% 미만이다.
- 확인: 직접 확인

### PERF-04 가만히 있을 때 메모리가 기준 이하다
- 조건: 조작 없이 그대로 둔다
- 결과: 관련 프로세스 메모리 사용량 합이 Windows는 150MB 이하, macOS는 120MB 이하다.
- 확인: 직접 확인

### PERF-05 설치 파일이 작다
- 결과: Windows 설치 파일과 macOS dmg가 각각 15MB 이하다.
- 확인: 자동 테스트
